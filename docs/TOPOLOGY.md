# Topology interface (Stage 04)

The reference graph is a synthetic fly-inspired directed graph, not a measured connectome. Stage 04 extracted its construction without changing the model's numerical behavior. Stage 05 adds `degree_preserving_rewired` and `random_sparse` controls through the same interface.
Stage 05 control kinds and checkpoint provenance are specified in [TOPOLOGY_CONTROLS.md](TOPOLOGY_CONTROLS.md).

`build_topology("fly_like", hidden_size=..., num_modules=..., num_populations=..., population=..., sparsity=..., reciprocal_fraction=..., hub_fraction=..., seed=...)` returns a frozen `GraphArtifact`. The consumer supplies an int64 CPU population assignment for each node. `mask[dst, src] == 1` means an edge from `src` to `dst`; `dst, src` follow `mask.nonzero()` lexicographic destination-major order. The artifact contains CPU contiguous `mask` (float32), source/destination and assignment arrays (int64), destination-major population-pair `edge_type`, incoming `degree` (float32), module IDs, direction, seed, schema version, resolved generation parameters, and a SHA-256 content hash. It is a data container, not a PyTorch module or checkpoint component.

`validate_graph` checks tensor shapes, dtypes, device and contiguity; edge bounds, order, uniqueness and no self-loops through exact mask correspondence; assignment bounds; incoming coverage; edge type, degree and hash consistency. `graph_statistics` reports density `E/(N(N-1))`, sparsity, exact incoming/outgoing degree lists, reverse-edge and within-module fractions, weak-component count, directed module modularity, population-pair edge counts, and zero-outdegree count. These statistics are descriptive; no benefit claim is made.

Foundation uses the artifact directly and registers only its existing five graph buffers (`dst`, `src`, `pop`, `edge_type`, `degree`) in the original order. The legacy FlyRNN mask function wraps the same builder and keeps its modulo population assignment; Foundation keeps its contiguous assignment. No graph metadata is persisted in model state. Existing format-v1 checkpoints load strictly, and a missing `topology` field resolves to `fly_like` for resume comparison. The checkpoint format remains 1.

Regression evidence: `tests/fixtures/stage04_fly_like_golden.json` records five pre-refactor seeded edge hashes including no-hub and hub cases. Runtime-generated format-v1 tests cover strict load and resume. Ignored `outputs/stage04/` holds the pre-refactor CPU state/order/forward/backward snapshot and comparison script; it is local evidence, not a public checkpoint dependency. CUDA behavior remains unverified on the current CPU-only environment.
