# Stage 03 robustness evaluator

The offline `flyts evaluate-robustness` command evaluates a local checkpoint against the same hash-verified corpus manifest. It accepts only `train` or `val` windows and rejects final-held-out domain roles. Stage 03 uses development evidence only.

```powershell
.venv\Scripts\python.exe -m flyts evaluate-robustness --manifest data/public-v1/manifest.json --checkpoint outputs/stage03/seed7/last.pt --config configs/evaluation/robustness-v1.json --output outputs/stage03/eval-seed7 --split val --device cpu --threads 2
```

The output directory must not exist. `records.jsonl` retains every window, arm and metric row, including the hash of its actual sampled target/view fixture. `summary.json` stores stable results and hashes separately from runtime environment/timing; `summary.csv` and `SUMMARY.md` repeat the same scalar summaries. Stable provenance includes the Git commit (or explicit `unavailable`), full evaluator config/master seed, manifest and checkpoint hashes, and checkpoint training seed/optimizer steps/parameter count where available. The top-level fixture hash binds the evaluator fixture version and every sampled fixture ID. Keep raw rows and checkpoints under ignored `outputs/`. The JSON schema is `schemas/robustness-result-v1.schema.json`. Config schema version 1 and report schema version 1 are candidate contracts.

Each raw position-wise row stores its window mean and `target_count`. Within one manifest record, window means are weighted by their valid target counts, yielding the mean over valid positions. Manifest records then have equal weight within each domain, and domains have equal weight in the primary macro result. Representation distances have no position denominator: their windows have equal weight within a record. Paired degradation aggregates each arm's losses by this rule before taking the relative difference. The `stable.aggregation` block records these rules with every result.

Fixture seeds derive from SHA-256 of schema version, master seed 3007, manifest hash, manifest record index, absolute window start, metric namespace and repeat. The evaluator does not call the training mask sampler. Reconstruction uses deterministic temporal ratio 0.4 and Smooth L1 `beta=1.0`. The training-fitted preprocessing remains train-visible only. Paired reconstruction uses a separate nonparametric, record-local reference coordinate from context visible to *both* views; masked targets, artificial missingness, channel dropout, originally missing values and padding are excluded. Each pair uses one reference for raw predictions and targets; a changed corruption pattern recomputes that reference. This is scoring geometry, not model fitting or a cross-record preprocessing estimate. Stage 2 masks and checkpoint version 1 remain unchanged.

For channel permutation, identity and up to eight unique nonidentity permutations per window use global embedding `1-cosine`; relative L2 is diagnostic. Zero-norm values are explicitly undefined. Dropout views use eight nested hashed channel orders at 0/10/30/50%, with stochastic rounding and at least one channel retained. A rate is compared against the paired zero-dropout view on the same surviving target subset. Single-channel dropout is a no-op. Unseen channel counts are deterministic nested views; nearest seen ties choose the smaller count. Interpolation and extrapolation are distinct arms. Count and dropout degradation aggregate each arm's losses to equal-record/equal-domain macro before taking the relative paired difference.

Padding adds one full patch, one padded channel, and both; representation distance and shared-target loss change are reported. Missingness applies MCAR and contiguous blocks at 10/30/50%, four repeats, only to originally observed non-target context. Missing values, padding, target corruption and channel dropout remain distinct. Small paired denominators yield an explicit undefined relative result and retain absolute change. All numerical floors are candidates until user approval.

The current CLI is an evaluator calibration tool. Its results do not establish final robustness, foundation quality, transfer, topology superiority or CUDA behavior. Public calibration requires the exact approved starter manifest SHA-256 `e538e9cbf761577740f43f6930ac4653834fdc00f9d0ee567b02b52e2d0d14eb`.

The approved development calibration uses `configs/evaluation/calibration-train-seed{7,17,29}.json`: two epochs of 200 optimizer steps, batch size 4, and `--development-only` verification that opens train/val arrays only. Each run uses its uniformly trained `last.pt`. The trainer's historical `best.pt` and window-weighted validation log are not a Stage 01 primary-selection claim. Exact public manifest bytes use canonical LF serialization on all platforms. `tools/calibrate_robustness.py` combines the three ignored evaluator runs into the small tracked `reports/robustness/calibration-candidate-v1.{json,csv,md}` brief with 10,000 candidate paired hierarchical bootstrap resamples. The raw JSONL and checkpoints stay under ignored `outputs/stage03/`.
